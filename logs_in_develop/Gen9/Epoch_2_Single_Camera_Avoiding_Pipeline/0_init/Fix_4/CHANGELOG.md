## 1. Motivation

`config/visual_avoiding_eval.yaml` was created as a minimal stub with:
- `projection_variants: []` — EMPTY (caused entire eval loop to be silently skipped, Fix-3 round 3)
- `geo_constraint_variants: []` — EMPTY
- No obstacle geometry, no halfspace geometry, no tightening

`config/projection_eval.yaml` (the non-visual D3IL avoiding eval config) has:
- Full `projection_variants` list (11 variants, matching the DPCC paper)
- Obstacle constraints: 3 sphere positions (approximate)
- Halfspace constraints: hard `\` and `/` shapes
- `enlarge_constraints: 0.025`

**Same task, same env (`ObstacleAvoidanceEnv`), same obstacles** — there is no reason not to reuse this content.

---

## 2. Design decisions

### 2.1 Format: `geo_constraint_variants` (not the flat `projection_eval.yaml` structure)

The visual eval scripts hardcode `open('config/visual_avoiding_eval.yaml')` and expect the `geo_constraint_variants` outer-loop format (same as `visual_aligning_eval.yaml`). `projection_eval.yaml`'s flat structure (`constraint_types: [...]`, `obstacle_constraints: {}`) is NOT read by these scripts — the visual eval's `setup_dpcc_projector` reads from the per-variant `geo_config` dict, not from a flat top-level key.

Therefore: **reuse the content** (geometry, variant list, tightening value) but **translate to the correct format**.

### 2.2 Obstacle positions: exact from `get_obj_xy_list()`, not approximated

`projection_eval.yaml` had 3 obstacles at positions with ~25mm error:
```
[0.4, 0.08]  vs  [0.425, 0.08]  (env truth)
[0.6, 0.08]  vs  [0.575, 0.08]  (env truth)
[0.5, -0.1]  vs  [0.5, -0.1]   (matches)
```
and only covered rows 1 & 2. The env (`get_obj_xy_list()`) has 6 obstacles in 3 rows.

`visual_avoiding_eval.yaml` provides TWO obstacle variants:
- `obstacles_exact` / `dynamics_obstacles_exact`: radius=0.04, all 6 obstacles, exact positions → matches training config (`_AVOIDING_OBSTACLES` in `avoiding-d3il-visual.py`)
- `obstacles_paper` / `dynamics_obstacles_paper`: radius=0.06, all 6 obstacles at exact positions → matches DPCC paper ablation radius scale

### 2.3 Not ported from `projection_eval.yaml`

| Field | Reason not ported |
|---|---|
| `avoiding_halfspace_variants` | Non-visual eval script format; visual scripts don't read it |
| `n_trials` | Replaced by `n_contexts × n_trajectories_per_context` |
| `observation_indices`, `action_indices` | Hardcoded in `setup_dpcc_projector`; yaml value never read |
| `bounds` | Velocity-bound format `{type,dimensions,values}` incompatible with visual eval's `workspace_bounds: {lb,ub}` |
| `plot_how_many`, `ax_limits` | 2D matplotlib plotting; visual eval uses MuJoCo GIFs |

## 3. New yaml structure

### Projection variants (11 — identical to `projection_eval.yaml`)
```
diffuser, dpcc-r, dpcc-c, dpcc-t, gradient, post_processing, model_free,
dpcc-c-dt0p25, dpcc-c-dt0p5, dpcc-c-dt2p0, dpcc-c-dt4p0
```

### Geo constraint variants (7 named entries)

| Name | Constraint types | Notes |
|---|---|---|
| `no_constraint` | `[]` | Baseline — raw diffusion, no projection |
| `obstacles_exact` | `['obstacles']` | 6 spheres r=0.04 — matches training config |
| `obstacles_paper` | `['obstacles']` | 6 spheres r=0.06 — matches DPCC paper radius |
| `dynamics_only` | `['dynamics']` | Euler kinematic link only |
| `dynamics_obstacles_exact` | `['dynamics', 'obstacles']` | Standard DPCC, r=0.04 |
| `dynamics_obstacles_paper` | `['dynamics', 'obstacles']` | Standard DPCC, r=0.06 |
| `combined_hard` | `['dynamics', 'halfspace', 'obstacles']` | Full avoiding DPCC; halfspace from `projection_eval.yaml` |

### Active variants for first cluster run

```yaml
active_geo_variants: ['no_constraint', 'obstacles_exact']
```

2 geo × 11 projection = 22 variant runs. Covers the baseline and the primary obstacle metric. Enable all via `active_geo_variants: null` once verified.

### Tightening
`enlarge_constraints: 0.025` (same as `projection_eval.yaml`). Tightened sibling auto-generated by the geo loop for any variant with obstacle/halfspace constraints.
