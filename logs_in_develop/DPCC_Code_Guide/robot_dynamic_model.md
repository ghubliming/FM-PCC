# DPCC Robot Dynamics & Control Guide

This document explains the mathematical and programmatic bridge between the 2D positional trajectories generated by the DPCC (Diffusion Policy with Constraints) model and the actual physical torque commands executed by the robotic arm in the MuJoCo simulation via the `d3il` framework.

## 1. The High-Level Abstraction (DPCC)
When you run DPCC (e.g., in `scripts/eval.py`), the diffusion model or Flow Matching process generates a trajectory of purely kinematic 2D points `[x, y]` for the robot's end-effector. DPCC does not natively understand joint limits, inertias, or actuator torques. 

```python
# DPCC scripts/eval.py
action, samples = policy(conditions={0: obs}, batch_size=args.batch_size, horizon=args.horizon)
next_pos_des = action + obs[:2]  # Calculate the next desired 2D position
obs, rew, terminated, info = env.step(np.concatenate((next_pos_des, fixed_z, [0, 1, 0, 0]), axis=0))
```
As shown above, the 2D output is padded with a `fixed_z` height and a fixed quaternion `[0, 1, 0, 0]` (which points the Panda arm's end-effector downwards) to create a full 7D Cartesian pose $X_{des} \in \mathbb{R}^7$.

## 2. The Environment Interface (d3il)
The `env.step()` function passes this 7D pose into `d3il`'s `ObstacleAvoidanceEnv`. 
Inside `ObstacleAvoidanceEnv` (`environments/d3il/envs/gym_avoiding_env/gym_avoiding/envs/avoiding.py`), the environment wrapper directly relies on a `MjRobot` instance (a simulated MuJoCo Franka Panda arm) which uses a Cartesian tracking controller:
```python
controller = robot.cartesianPosQuatTrackingController
```

## 3. Cartesian Impedance Control & Iterative IK
The controller handling this 7D Cartesian setpoint is the `CartPosQuatImpedenceController` defined in `environments/d3il/d3il_sim/controllers/IKControllers.py`. This controller's job is to convert the spatial Cartesian error into desired joint positions $q_{des}$, velocities $\dot{q}_{des}$, and accelerations $\ddot{q}_{des}$.

### The Math:
1. **Spatial Error Calculation**: It calculates the positional error $e_p$ and quaternion orientation error $e_q$.
   $$ \ddot{X}_{target} = \begin{bmatrix} K_{p, pos} (X_{des} - X_{curr}) \\ K_{p, quat} \cdot quat\_err(q_{des}, q_{curr}) \end{bmatrix} $$

2. **Inverse Kinematics (IK) via Jacobian Pseudo-inverse**: It uses the robot's Jacobian matrix $J(q)$ to map the Cartesian space accelerations to joint space. To handle kinematic redundancies (the Panda has 7 DoF for a 6 DoF task) and prevent singularities, it uses a damped least-squares (Levenberg-Marquardt) approach with a Null-space projector to keep joints near a rest posture $q_{rest}$:
   $$ (J W J^T + \lambda I) \Delta q = \ddot{X}_{target} - J \dot{q}_{null} $$
   $$ \Delta q_{final} = W J^T (J W J^T + \lambda I)^{-1} (\ddot{X}_{target} - J \dot{q}_{null}) + \dot{q}_{null} $$
   Where $\dot{q}_{null} = K_{null} (q_{rest} - q)$ pushes the robot to a comfortable configuration without affecting the end-effector.

3. **Joint Derivatives**: The controller iteratively applies $\Delta q$ to find $q_{des}$, and then numerically differentiates to find the joint velocities and accelerations to pass down to the lower-level controller:
   $$ \dot{q}_{des} = \frac{q_{des} - q_{old}}{dt}, \quad \ddot{q}_{des} = K_{d, joint} \frac{\dot{q}_{des} - \dot{q}_{old}}{dt} $$

## 4. Computed Torque Feedforward Control
The lower-level joint controller is the `ModelBasedFeedforwardController` (`environments/d3il/d3il_sim/controllers/Controller.py`). This is where the physics and dynamics actually happen. 

It calculates the required torque $\tau$ using a **Computed Torque (Inverse Dynamics)** control law:
$$ \tau_{PD} = K_p (q_{des} - q_{curr}) + K_d (\dot{q}_{des} - \dot{q}_{curr}) $$
$$ \tau_{FF} = M(q_{des}) \ddot{q}_{des} + C(q_{des}, \dot{q}_{des}) $$
Where $M(q)$ is the Mass/Inertia matrix and $C(q, \dot{q})$ are the Coriolis and centrifugal forces. It returns $\tau_{PD} + \tau_{FF}$.

## 5. Gravity Compensation and Actuation
Finally, the torque is passed to `MjRobot.preprocessCommand()` in `environments/d3il/d3il_sim/sims/mj_beta/MjRobot.py`.
1. **Gravity Compensation**: The robot adds the gravity compensation term $G(q)$ calculated by MuJoCo's `mj_inverse` or `qfrc_bias`.
   $$ \tau_{final} = \tau_{PD} + \tau_{FF} + G(q_{curr}) $$
2. **Execution**: The final torques are clipped to the hardware limits of the Panda arm (`self.torque_limit`) and written directly to the MuJoCo actuator controls:
   ```python
   self.scene.data.ctrl[self.joint_act_indices] = self.uff.copy()[: self.num_DoF]
   ```
3. MuJoCo's forward dynamics engine integrates these torques to move the physical robot mesh in the simulator.

---
### Summary
While DPCC "feels" like it's just moving a dot on a 2D plane, underneath it is triggering a complex cascade of **Jacobian-based Inverse Kinematics**, **Null-space redundancy resolution**, and **Model-based Computed Torque Control**. This ensures that the heavy, nonlinear physical robotic arm tracks the 2D positional trajectory perfectly while obeying its own mass, inertia, and joint-limit constraints in the MuJoCo physics engine.
