## KP1 — "The UAV trajectory generation method must be stated somewhere"

**Added:** `\subsubsection*{Expert demonstrations}` at the end of §4.7.3 *Quadrotor Scenes*
(`sec:method:env:uav`). It tells the two layers as method, with three new equations:

| equation | content |
|---|---|
| `eq:method:env:uavref` | waypoint chain → straight segments + circular arcs of radius ≤ r_f (clamped to ≤ ½ of either segment) → arc-length path `p_path`; one cosine speed profile `s(t) = (L_path/2)(1 − cos(πt/T_ep))` |
| `eq:method:env:uavrefderiv` | `ṗ_des = p_path′ ṡ`, `p̈_des = p_path′ s̈ + p_path″ ṡ²`, the feed-forward terms of `eq:method:dep:outer` (centripetal on arcs, zero on segments) |
| `eq:method:env:uavdata` | recording at the planning rate, every `n_dec`-th physics step: `o_j = (p_des, p, ṗ)`, `a_j = p_des(t_{j+1}) − p_des(t_j)` — the form of `eq:method:dep:setpoint`–`eq:method:dep:obs` |

The prose also covers:
- homotopy classes fixed by the waypoints and cycled across episodes;
- the per-episode randomisation: altitude and duration; start and end in the empty scene; a start
  offset in the corridor's centre lane; a path offset in the s-curve;
- execution by the cascaded geometric tracking controller of §4.6.3, from rest and level;
- the two rejection rules: contact fraction above a scene threshold, and altitude below a minimum;
- the closing point: *the action is the increment of the reference, not an output of the
  controller*.

**Verified against the code, not the notes:**

| claim | code |
|---|---|
| waypoint chains per scene / homotopy | `uav_expert_data_collect/trajectories.py` |
| circular arcs, radius clamp, global cosine profile, centripetal `a_des` | `uav_env_test/trajectories.py:114–` (`blended_path`); straight scenes `:67–90` (`traverse_line`) |
| randomisation, controller loop at `Δt_phys`, rejection | `uav_expert_data_collect/generator.py` (`_build_traj_and_init`, `run_trial`, `SCENE_MAX_CONTACT_FRACTION`, `Z_FLOOR_MARGIN`) |

| stride 3 = `n_dec`, `obs = [p_des, p, v]`, `actions = diff(targets)` | `dataset_writer.py` |

**Left out on purpose:**
- **The per-episode offset on `targets`.** It is added before the difference, so it cancels in
  `actions`, and `obs` is built from the un-offset reference. It changes nothing the model sees.
- **Scene values** (r_f, thresholds, ranges). They are configuration values and belong to v3's
  `sec:setup:data`.
- **The gain variants.** `collect.py` takes a single gain variant per call, so which variants make up
  the corpus is not recorded in one place.

**Note corrected:** `Auxiliary/Methodology_Sources/AUX_uav_expert_data.md` said *"cubic fillets"*,
but the code has **circular arcs**. Fixed there, with a dated line.

- It trains from `x₀ ~ N(0, I)` (`flow_matcher_v3/models/diffusion.py:284`) but samples from

  off the training distribution.

- Gen3v6 fix_4 fixed only the endpoint-projection port for MeanFlow, and
  `ENGINE_INIT_NOISE = {'fm': 0.5, …}` keeps the flow-matching value on purpose, to stay consistent.
- Nothing was changed in code.

## KP3 — "§4.3.6 *Concatenated conditioning (the shipped default)* — BS. We only have and use the first one; give it a proper name (and add it to the translation table); never mention the second."

**Proper name:** **feature-wise conditional biasing**. The FiLM paper names exactly this mechanism
(Perez et al., §3, verified in `VLA/FiLM.pdf` p. 3): *"concatenating conditioning information with
fully-connected layer input amounts to a feature-wise conditional bias."* Cited in place as
`\parencite[Sec.~3]{perez2017film}`, and the word *FiLM* is not used.

**Changed in §4.3.6 (`sec:method:backbone`):**
- The two-item description list is gone (*Concatenated conditioning (the shipped default)* /
  *Affine (true FiLM) conditioning (the ablation)*).
- Equation `eq:method:backbone:film` is gone.
- Remark `rem:naming` (*The default is not FiLM, and the code's name for it says otherwise*) is gone.
- One paragraph now states the mechanism, with `eq:method:backbone:concat` unchanged: the latent is
  projected, concatenated with the time embedding, and reaches every residual block through the
  additive bias of `eq:method:backbone:block`.

Tone fixes in the same subsection. Each removed item is defensive, self-talk or jargon; no method
content was lost:
