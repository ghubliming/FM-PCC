# From v3.58 to v2 — exact tensors and corrected transport-time law

**Date:** 2026-09-21 · **Source:** v3.58 Chapter 5 / appendix · **Target:** Chapter 4 Method.

The older `FROM_v3_20260920_v3.47_transport_time_sampling.md` contains a **wrong sign** for the
instantaneous-velocity matching time law. Do not copy its proposed formula or its claim that the draw
weights the data end. The implementation draws $U\sim\operatorname{Beta}(1.5,1)$, then passes
$\tau=1-U$ to the network (`mix_visual_aligning/models/fm_diffusion.py:300--307`; likewise
`flow_matcher_v3/models/diffusion.py:305--306`). On Chapter 4's noise-at-zero, data-at-one axis,
$\tau\sim\operatorname{Beta}(1,1.5)$ and $p(\tau)=1.5(1-\tau)^{1/2}$. This weights the **noise end**.
v3.58 defines the correct discrete diffusion, reflected Beta and logit-normal pair laws in
`v3/chapters/09_appendix.tex`, `app:training-time-laws`. The author chose the appendix as the home for
their detailed mathematics, so Chapter 4 can give the correct short description and point forward.

Chapter 4's `eq:method:plan` currently says that horizon $H$ means $H+1$ state–action pairs and
$n=(H+1)d$. The reported training windows and denoising-model inputs/outputs are instead
$(N,H,d)$ with **$H=8$ actual transitions** ($N$ is training batch size; $B$ is already the candidate-plan count in Chapter 5). Please reconcile the definition/indexing with the
implementation rather than changing the Chapter 5 values. The precise layouts are:

| environment | current state anchor | model input/output plan | other conditioning |
| :-- | :-- | :-- | :-- |
| D3IL-avoiding | $(N,4)$ | $(N,8,6)$: action 2 + commanded position 2 + measured position 2 | none |

| UAV scenes | $(N,9)$ | $(N,8,12)$: action 3 + commanded position 3 + measured position 3 + measured velocity 3 | none |
