## §5.3.3 Quadrotor baseline
- Precedent: the quadrotor task shipped with MuJoCo MPC — same X2 model; Predictive Sampling, 32
  trajectories, 5 spline points, 0.5 s horizon, 0.01 s step; cost on goal distance, velocities and
  hover thrust; 13-goal loop advancing within 0.5 m. Read from `mjpc/tasks/quadrotor/`. The MJPC paper
  does not evaluate this task; stated so. Differences: learned plan vs optimisation on the true model;
  walls/pillars/slide vs gates; tracked setpoints vs rotor commands.
- Corrected before commit: D3IL table number (3, not 2); removed a claim that our gate geometry comes
  from MJPC — `gates.xml` is a byte-identical copy but no scene uses it.

## §5.5 — training and evaluation parameters
- `tab:train` and `tab:eval`, each parameter with its meaning. **Values come from the resolved trainer
  configs in the training logs** (job IDs in the `\srcnote`), not from the current config files, which
  no longer reproduce several thesis checkpoints (e.g. flow matching `aw1` vs the `aw10` checkpoint;
  MeanFlow/consistency-training defaults DiT/SiT vs the U-Net runs).
- 🔴 **Training is not uniform**, contrary to the working assumption — now stated in a `\guard`:
  - obstacle avoidance: MeanFlow and consistency training at batch 32×2, lr 5e-4; diffusion and flow
    matching at 8×2, lr 1e-4 (diffusion identical to DPCC's upstream config);
  - alignment: all 64×2, lr 2e-4, but action loss weight 10 for diffusion vs 1 for the flow models;
  - quadrotor: uniform, 8×2, lr 1e-4, action weight 1;
  - weights evaluated: EMA only for MeanFlow and consistency training on obstacle avoidance; raw weights
    everywhere else (DPCC's own eval uses raw).
- Evaluation: B=4, η=0.5, tightening 0.025 (+0.31 m vehicle radius), replanning every step, episode
  limits 200 / 400 / 396·634·871; checkpoint = lowest held-out loss.
