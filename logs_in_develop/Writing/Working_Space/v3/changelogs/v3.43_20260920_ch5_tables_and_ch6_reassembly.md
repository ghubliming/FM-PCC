## 0 · 🔴 The action loss weight is gone from the thesis

**The author's question — "is it true we use a different action weight? and for the UAV is it still this
thing?" — the answer is yes, and it is worse than Table 5.8 said.**

| environment | diffusion baseline | flow-based models |
| :-- | :-- | :-- |
| D3IL-avoiding | 10 | FM 10; MeanFM / CI-MeanFM: key set to 10 but **never applied to the loss** (FIX-3) |
| D3IL-aligning | 10 | **1** |
| UAV, all three scenes | **1** | **1** |

So on the quadrotor the arm that exists to *be* the DPCC baseline is not trained in DPCC's configuration,
and its own config says so (`config/uav_mix.py:497-503`, declared deviation). On the two average-velocity
engines `_aw10` in a checkpoint path is a **naming artefact**: `flow_matcher_v3_meanflow/models/mf_diffusion.py:49-52`
keeps the key for folder naming and the `state_dict` and never multiplies the objective by it.

**Author's decision: no time to fix — record it and remove it.** Fixing means retraining three UAV arms
plus three aligning flow models. The flaw is written up in full, including what a fix would cost, in
[`../../data_status/FLAW_20260920_known_flaws.md`](../../data_status/FLAW_20260920_known_flaws.md),
registered in the data-status `INDEX.md`.

Removed from the draft, everywhere it appeared:

* §5.5.1, the baseline description — the clause "action loss weight $10$" deleted.
* `tab:train` (Table 5.8) — the **Action loss weight** row deleted.
* the `\guard` under `tab:train` — the clause about D3IL-aligning weighting the first action ten times
  more heavily for diffusion than for the flow models, deleted.
* the `\srcnote` under `tab:train` — the `a1.5_b1.0_aw10` checkpoint token removed.
* `tab:state-models` and `fig:avoiding-raw-models` captions — "identical width, depth, action loss weight
  and time sampler" → "identical width and depth".
* §6.3 lead-in — "trained with $\nfe=20$ and action loss weight $1$" → "trained at $\nfe=20$".

One consequence had to be followed through: `tab:train`'s caption said the baseline's configuration was
"trained on the data of the other two environments" **unchanged**, which the deleted row was the evidence
against. It now says the same model and backbone are trained on each environment's data with the settings
the table lists --- which is what actually happened.

**What this does not do:** it does not turn a false claim into a vague one. Nothing in the draft now
claims the models are matched on the loss weighting, or that the UAV diffusion arm reproduces DPCC's
training configuration. The matched-training claims that remain — backbone, parameter count, dataset,
plan horizon, step budget — are all true as written.
