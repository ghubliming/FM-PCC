# v3.23 — 2026-09-17 · monochrome table emphasis

## Decision

The TUM/I6 material inspected for this thesis does not explicitly prohibit colour in result tables.
Nevertheless, red was a poor final-document convention because it made the table semantics depend on
colour, could disappear in grayscale printing, and competed with figures in which colour encodes data.

The final-text convention is now monochrome: **bold identifies the selected configuration**. In Table
6.2, bold already identifies each model's best selection rule, so the caption names the selected
five-seed operating point explicitly instead of assigning a second meaning to the same typography.

## Changes

- `\mainconfig{}` now expands to `\textbf{}` without `\textcolor{red}`.
- The captions of Tables 6.1, 6.3 and 6.4 say that bold marks the selected configuration.
- The caption of Table 6.2 states the selected operating point directly: MeanFM, $\nfe=1$, temporal
  consistency.

## Colour audit

No other colour command in the live chapter source is intended as final result styling. The remaining
colours belong to drafting diagnostics: `\hole`, `\srcnote`, `\dataref`, `\provisional`, `\guard`, and
the missing-figure box. `tools/check.py` counts these explicitly, and all uses must be resolved or removed
before submission. Plot colours remain legitimate data encodings and are outside this table-style
hotfix.
