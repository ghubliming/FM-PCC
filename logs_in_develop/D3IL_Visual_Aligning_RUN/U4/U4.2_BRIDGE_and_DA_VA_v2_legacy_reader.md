# U4.2 — Legacy bridge + DA_VA_v2 legacy reader

**Date:** 2026-08-12 · **Epoch:** U4 · **Depends on:** U4.1 (data verified trustworthy except
`entropy`) · **Sibling:** U4.3 (the same layout, written natively by the eval)

**Goal:** make finished D3IL visual-aligning baseline runs readable by `Data_Analysis/DA_VA_v2`
without re-running them, and without teaching DA_VA_v2 a second data model.

**Shape of the solution:** a bridge script re-emits the old outputs into the *existing* Gen14 API
shape (spec §1 "shape C") under a root whose name starts with `_`. DA_VA_v2 treats a `_`-prefixed
root as **legacy** and turns on a small rescue pass; everything else — discovery, loading,
aggregation, reporting — is the code that already existed.

## 1. The bridge

```bash
# cluster (numpy present) — every agent, every seed
python d3il_visual_aligning_baseline_test/bridge_d3il_va_to_da_va_v2.py \
    --source-root logs/d3il_visual_aligning_baseline

# path/JSON logic only, no npz, no numpy (this is what runs in the AI container)
python ... --json-only
```

Reads (never modifies) the original layout:

```
logs/d3il_visual_aligning_baseline/{agent}/seed_{s}/
    results_seed_{s}.json
    diagnostics/rollout_{r}_stats.json
    realtime_baseline_ctx{c}_traj{t}.log
```

Writes:

```
logs/d3il_visual_aligning_baseline/_DA_VA_BRIDGE_d3il_baseline/     ← "_" = legacy
    _bridge_manifest.json                                          ← legacy_kind, has_projector, per-unit provenance
    d3il_baseline_{agent}/                                         ← DA_VA_v2 candidate
        {seed}/
            config_snapshot_d3il_baseline/snapshot_{YYYYMMDD_HHMMSS}   ← "Last Run" column
            results/d3il_baseline/                                     ← DA_VA_v2 variant, geo=none
                d3il_baseline.npz
                unit_meta.json
                diagnostics/rollout_{r}_stats.json                     ← Gen14 nested schema
```

**Three things it fixes or fills**, all of them things the old files could not answer:

1. **`entropy` recomputed** from the per-rollout modes (U4.1 bug B1 — the stored value is a hard
   0.0). The broken value is preserved as `args.entropy_legacy_broken` for the audit trail.
2. **`avg_time`** parsed from the RTRecorder `SUMMARY` line (`total_ms mean=…`) of each
   `realtime_baseline_ctx{c}_traj{t}.log` — the only place the old eval kept timing. Missing log ⇒
   NaN, never a guess.
3. **context / traj indices** reconstructed from the eval's context-major loop order
   (`rollout = ctx·n_trajs + traj`) and cross-checked against `context_info.context_idx`; a
   disagreement is printed and the JSON wins.

It also re-derives `success_rate` from the rollout JSONs and warns when that disagrees with
`results_seed_{s}.json` — the cheap detector for a partially-downloaded diagnostics folder.

**Not written: any `constraint_*` key.** This baseline runs no projector, so those metrics do not
exist; absent ⇒ NaN in the DA tables. Writing 0 would make the baseline look perfectly
constraint-satisfying and would poison `n_success_and_constraints`.

## 2. DA_VA_v2 side

**The contract is the `_` prefix** (`config.LEGACY_DIR_PREFIX`), backed by
`_bridge_manifest.json` when present. No registry of pipeline names to keep in sync.

* `discovery.detect_legacy(candidate_path, parent_root)` — walks up for the manifest, checks the
  path components for a `_` prefix, returns `{legacy, legacy_kind, has_projector,
  bridge_manifest_path, manifest}`. Merged into every candidate and carried on every unit; also
  logged, printed in the candidate summary, and written into `discovery_manifest.json`.
* `data_loader._apply_legacy()` — runs after the normal load for legacy units only:
  * rescues `avg_time` from `realtime_*.log` when the unit has none (covers `--json-only` bridges
    and hand-copied trees); records the source in `data_quality.csv`;
  * warns if a projector-free pipeline somehow carries *populated* constraint columns (all-NaN is
    normal — the JSON reader always creates them);
  * never fabricates a constraint value.
  Quality rows gain `legacy`, `legacy_kind`, `has_projector`.
* `aggregator._metric_mean/_metric_std` — fall back when the metric is **missing OR all-NaN**
  (was: missing only). Without this a projector-free candidate ranks as NaN and disappears from
  the comparison instead of ranking on plain goal success.
* `reporter` — `data_quality.csv` leads with the three new columns; the TXT ranking tags such a
  candidate `[LEGACY …] [no projector: ranked on goal success only]`; NOTES explains it.

**What the D3IL baseline looks like in the tables:** `variant=d3il_baseline`, `geo=none`,
`split=test`, one candidate per agent, one unit per seed. Comparable on `n_success`,
`mean_dist_per_rollout`, `n_steps`, `avg_time`, `context_*`; NaN on everything constraint-shaped,
by design.

**`avg_time` semantics differ from Gen14** and are recorded in `args.timing_semantics`: D3IL calls
the policy on *every* control step (the action chunk is served from the agent's internal buffer),
so this is **seconds per control step**, while Gen14's `avg_time` is per replan. Do not put them in
one column without saying so.

## 4. Applied to the two real legacy trees (2026-08-12)

Checked against a `tools/capture_tree` capture of both roots
(`temp/1208/Gen14_Mix_FilmV2/legacy_d3il_va_tree.txt`); both bridge cleanly, but
they collide and needed two flags added.

| | `logs/d3il_visual_aligning_baseline/` (post-U3) | `logs/d3il_visual_aligning_baseline(Bf_U3)/` |
|---|---|---|
| size | 5525 files, 1.4 GiB | 11331 files, 4.1 GiB |
| seeds with eval data | **only `seed_42`** (1080 rollouts, complete) | all 6 (`0-4`, `42`), **462–473 rollouts each = ~43 % of 60×18** |
| `results_seed_{s}.json` | yes | **absent** (killed before the final write) |
| `realtime_baseline_*.log` | 1080, 131 MiB | **none** |
| seeds 0–4 | `weights/` only, no `.pth`, 1.4 KiB train log ⇒ **training died early, never evaluated** | trained + partially evaluated |
| bridged result | 1 unit, `timing=1080/1080` | 6 units, `timing=0/…`, flagged `[ PARTIAL ]` |

Three consequences, all handled:

1. **Seed collision.** Both trees hold `ddpm_encdec_vision/seed_42`, i.e. the same
   candidate/seed output path — the second bridge would have silently overwritten the first.
   Added **`--label`** (→ `d3il_baseline_ddpm_encdec_vision__Bf_U3`) plus a guard that refuses to
   overwrite a unit bridged from a different `legacy_source_dir` and names the fix
   (`--force` overrides).
2. **No `results_seed_*.json` ⇒ no scale.** Inference from the rollout JSONs recovers
   `n_trajs = 18` correctly for every partial seed, but reports `n_contexts = 26/27` (the contexts
   actually reached) instead of 60. That is the honest entropy denominator, and wrong if you want
   the launched scale. Added **`--n-contexts` / `--n-trajectories`** to pin it, and a
   `[ PARTIAL ]` line reporting `462/1080 (43%) — contexts 0..25 of 0..59`, plus
   `args.partial_run` / `args.n_rollouts_expected` in the npz.
3. **No realtime logs ⇒ no timing.** `avg_time` is NaN for all Bf_U3 units and serialises as
   JSON `null`. DA_VA_v2's legacy pass then reports `legacy_avg_time_source=missing` in
   `data_quality.csv`. Nothing is invented.

**Partial runs are not a random subsample** — the eval loops context-major, so a killed run
covers the *low-index contexts only*. Success rates from Bf_U3 are over contexts 0–26, not over
the test set; do not compare them head-to-head with a complete run without saying so.

Recommended invocation for the pair:

```bash
python d3il_visual_aligning_baseline_test/bridge_d3il_va_to_da_va_v2.py \
    --source-root "logs/d3il_visual_aligning_baseline"
python d3il_visual_aligning_baseline_test/bridge_d3il_va_to_da_va_v2.py \
    --source-root "logs/d3il_visual_aligning_baseline(Bf_U3)" \
    --out-root    "logs/d3il_visual_aligning_baseline/_DA_VA_BRIDGE_d3il_baseline_Bf_U3" \
    --label Bf_U3 --n-contexts 60 --n-trajectories 18
# both roots in one comparison
python Data_Analysis/DA_VA_v2/main_da_batch.py --parent-path \
  "logs/d3il_visual_aligning_baseline/_DA_VA_BRIDGE_d3il_baseline,logs/d3il_visual_aligning_baseline/_DA_VA_BRIDGE_d3il_baseline_Bf_U3"
```

## 5. Gotchas

* Point `--parent-path` at **one** root. Both the bridged (`_DA_VA_BRIDGE_…`) and native
  (`DA_VA_d3il_baseline`) roots live under `logs/d3il_visual_aligning_baseline/`, so passing the
  shared parent discovers the same seed twice, as two candidates.
* The original `{agent}/seed_{s}/` folders are **not** discoverable (`seed_42` is not a numeric
  directory name), so nothing is picked up twice by accident.
* Never name a fresh export root with a leading `_` — that would mark new runs legacy.
